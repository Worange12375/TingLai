# 听籁 SoundVerse · AdminTool 使用手册

> AdminTool 是项目自带的**本地素材处理工具**：在浏览器里改物种科普卡文字、听音频、传音频、批量降噪，改完一键写回仓库里的 JSON 文件。
>
> 一句话概括：**它把「用记事本手改 JSON + 命令行敲 ffmpeg」这套活，变成了点点鼠标。**

---

## 一、这个工具解决什么问题

物种科普卡的数据存在 `src/data/species.sample.json`（当前 30 条），每条 13 个字段。音频文件在 `public/audio/`，插画在 `public/assets/`。

如果不用工具，改一条物种要做这些事：

1. 用编辑器打开一个几千行的 JSON，找到那一条，小心翼翼别改坏括号
2. 想听听音频对不对，得自己去文件夹里翻文件双击播放
3. 换了音频要手动改文件名成 `<id>.mp3`、手动敲 ffmpeg 命令降噪
4. 改完不知道有没有写错字段名、有没有漏必填项
5. 改坏了没有后悔药

AdminTool 把这五件事全包了：**左边挑物种，右边听音频 / 传音频 / 改文字，点保存前给你看 diff，写入前自动备份。**

### 谁会用到它

| 角色 | 主要用途 |
|------|----------|
| **林知声**（物种知识官） | 主力用户。写科普文案、核对学名和保护级别、维护版权署名、换音频 |
| **主理人** | 抽查数据质量、看有没有红色错误、临时补字段 |
| **郝栈桥**（前端） | 核对字段结构和前端渲染是否对得上、排查识别映射问题 |
| **普通用户 / 评委** | **完全接触不到**，公开站点没有这个入口 |

## 二、怎么打开

### 三步

```bash
# 1. 进到仓库根目录
cd /path/to/SoundVerse

# 2. 起开发服务器
npm run dev

# 3. 浏览器打开下面这个地址
#    http://localhost:5173/#/dev
```

启动后终端会直接把地址打印出来，长这样：

```
  ➜  管理员工具: http://localhost:5173/#/dev  (仅开发环境)
```

按住 `Ctrl` 点一下就能打开。

### 注意地址里的 `#`

正确：`http://localhost:5173/#/dev`
错误：`http://localhost:5173/dev` ← 少了 `#`，打不开

项目用的是 HashRouter，所有页面地址都带 `#`。

### 为什么公开站点上没有这个入口（安全说明）

这一点值得说清楚，因为它是设计上刻意为之的：

**AdminTool 的代码根本不会进入生产构建产物。**

- 页面组件在 `src/App.tsx` 里由 `import.meta.env.DEV` 判断是否加载。生产构建时 Vite 把这个值静态替换成 `false`，打包器随即把整个分支连同 AdminTool 的代码一起删掉——`dist/` 里**不存在**这些代码。
- 后端能力（读写文件、跑 ffmpeg）由 `vite-plugin-admin.ts` 提供，这个插件声明了 `apply: 'serve'`，**只在 `npm run dev` 时挂载**。`npm run build` 完全不会加载它，生产环境不存在任何 `/__admin` 接口。

所以线上站点（含 CloudStudio 静态部署）访问 `/#/dev` 不会渲染管理员工具——这里本来就**没有** `/__admin` 接口，所以会显示「连不上后端」或普通页面，**这是预期设计，不是不稳定或 bug**。所有数据维护（上传/规范化/改名/保存）都必须在**本地 `npm run dev`** 下进行。**没有公开攻击面，不需要为它加鉴权。**

### 打不开怎么办

| 现象 | 原因 | 处理 |
|------|------|------|
| 页面显示「管理员工具连不上后端」 | 打开的是构建产物，不是 dev 服务器 | 确认是用 `npm run dev` 启动的，不是 `npm run preview`，也不是直接开 `dist/index.html` |
| 在 CloudStudio / 线上静态站打开 `/#/dev` 闪退或「连不上后端」 | AdminTool **只在本地 `npm run dev` 时存在**；CloudStudio 是静态产物，没有 `/__admin` 接口，所以这里用不了（这是预期设计，不是 bug） | 管理工作请在本地 `npm run dev` 打开 `http://localhost:5173/#/dev` 做；CloudStudio 只是给评委/用户访问的成品站 |
| 页面 404 | 地址少了 `#` | 用 `http://localhost:5173/#/dev` |
| 端口不是 5173 | 5173 被占用，Vite 自动换了端口 | 看终端实际打印的端口号 |

## 四、顶栏：先看这里

顶栏是**数据健康仪表盘**，每次打开先扫一眼。

| 显示项 | 含义 |
|--------|------|
| `src/data/species.sample.json · 共 30 条 · 映射表 N 个键` | 当前在编辑哪个文件、多少条数据 |
| 绿色 `✓ 校验通过` | 没有错误级问题，可以保存 |
| 红色 `✕ N 项错误` | **有 N 处硬伤，保存会被拒绝**，必须先修 |
| 粉色 `! N 项提醒` | 建议性问题（比如文案偏长），**不拦保存**，可以先放着 |
| `ffmpeg 就绪` / `ffmpeg 缺失` | 决定能不能做音频转码和批量降噪 |
| `重新载入` | 丢弃所有未保存改动，从磁盘重读 |
| `保存（N 条改动）` | 打开 diff 预览窗口 |

### 关于 ffmpeg

显示「缺失」时，**批量规范化按钮是灰的**，上传音频也无法转码。安装方法：

```bash
# Windows
winget install Gyan.FFmpeg

# macOS
brew install ffmpeg

# Ubuntu / Debian
sudo apt install ffmpeg
```

装完**重启 `npm run dev`**，徽章才会变绿。

> 没有 ffmpeg 也能用工具的其它功能，只是音频处理受限。见第六章。

## 五、左侧列表：找物种、选物种

### 找

- **搜索框**：支持中文名、学名、id 三种关键词，模糊匹配
- **类群下拉**：全部 / 鸟类 / 蛙类 / 昆虫
- **「只看有错」勾选框**：只显示有**错误级**问题的条目。**修数据时先勾上这个，把红点清完再干别的**

列表里名字后面带红色 `●` 的，就是有错误的条目。

### 选

- **点一行**（点在名字上）→ 右侧打开这条的详情
- **勾左边的复选框** → 加入批量操作队列（可多选）
- **全选 / 清空** → 对当前筛选结果批量勾选

### 批量操作区

勾选任意条目后，列表底部会出现批量操作面板：

| 操作 | 说明 |
|------|------|
| **规范化音频** | 对选中条目的音频跑 ffmpeg 降噪 + 响度归一（详见第七章） |
| **按源重抓** | 从原始外链重新下载音频到本地（详见第八章） |
| **批量改字段** | 把选中条目的某个字段统一改成同一个值 |

批量改字段只开放三个：`group`（类群）、`protectLevel`（保护级别）、`distribution`（分布）。

> ⚠️ **`audioSource` 和 `audioLicense` 被硬性禁止批量修改。**
> 这两个是逐条独立的版权署名，属于合规红线。工具会直接弹错误拒绝执行。想改只能在右侧详情里一条一条改。

## 六、右侧详情 · 音频区

### 左半边：听 + 下载

- **播放器**：直接试听当前物种的音频
- 下方一行小字是音频的实际地址（`/audio/xxx.mp3` 是本地文件，`https://...` 是远端外链）
- 顶部徽章会标注 `本地音频` 还是 `远端外链`
- **「下载原音频」按钮**：把音频存到本地。远端音频由后端代理下载，不受浏览器跨域限制，一定能下下来

### 右半边：上传修正音频

**这是最常用的功能。**

1. 点「选择文件」，挑一个音频（支持 mp3 / wav / m4a / ogg / flac）
2. 选完自动开始上传处理，不用再点确认
3. 处理完顶栏会提示写入结果和文件大小

**文件名随便取。** 工具会自动改名成 `<物种id>.mp3` 存进 `public/audio/`，并同步更新该条的 `audioUrl` 字段。你不需要自己重命名。

**「同时做响度规范化」勾选框**（默认勾上）：上传时顺便跑一遍降噪和响度归一。建议保持勾选，除非你上传的是已经处理好的成品。

#### 上传后必须做的一步

> **上传只是把文件落了盘，`audioUrl` 的改动还在草稿里，没写进 JSON。**
> **记得回顶栏点「保存」。** 不保存的话，刷新页面这个改动就没了（文件还在，但 JSON 里指向的还是旧地址）。

#### 没装 ffmpeg 时的行为

| 上传的文件 | 结果 |
|-----------|------|
| 本来就是 mp3 | 直接改名存入，能用 |
| 不是 mp3（wav / m4a 等） | 保留原格式存为 `<id>.wav` 等，`audioUrl` 也跟着改成对应扩展名。**不会谎报成 .mp3** |

装上 ffmpeg 后重新上传一次，就能统一成 mp3 了。

#### 其它限制

- 单文件上限 **50MB**
- 文件小于 512 字节会被拒绝（认定为空文件）

## 七、批量规范化音频（ffmpeg）

选中若干条目 → 点「规范化音频」。

### 它到底做了什么

对每条音频依次执行这四道处理：

| 处理 | 参数 | 为什么要做 |
|------|------|-----------|
| **高通滤波** | `highpass=f=120` | 砍掉 120Hz 以下的低频，主要是风噪、空调声、交流电流声。鸟叫蛙鸣基本都在这个频率以上，砍掉不损伤有效声音 |
| **响度归一** | `loudnorm=I=-16:TP=-1.5:LRA=11` | EBU R128 标准。让所有物种音频音量一致，用户切换物种时不会忽大忽小要反复调音量 |
| **首尾静音裁剪** | `silenceremove` 前后各一次 | 掐掉开头和结尾的空白，点播放立刻出声。**中间的静音会保留**——那是叫声本身的节奏，不能删 |
| **统一编码** | 单声道 / 44100Hz / 128kbps mp3 | 减小体积，加快页面加载 |

### 结果怎么看

处理完右侧会出现「批量执行结果」面板，逐条列出成功（绿色 ✓）或失败（红色 ✕）及原因。

### 同样要记得保存

规范化改的是**磁盘上的音频文件**，`audioUrl` 的变更还在草稿里。**处理完要回顶栏点「保存」写回 JSON。** 工具在提示里也会提醒你这一点。

## 八、按源重抓

选中条目 → 点「按源重抓」，从原始外链重新下载音频到本地。

**什么时候用**：本地音频文件误删了、处理坏了、或者想拿回未经处理的原始版本。

### 它从哪找原始链接

1. 如果这条的 `audioUrl` 现在还是 `https://` 外链 → 直接用它
2. 如果已经本地化了 → 从工具自己的存档 `.audio-origins.json` 里找

> 这个存档是工具在你每次打开时自动记录的：只要某条曾经以外链形式出现过，来源就被存下来了。它已被 gitignore，属于本机文件，**换台电脑就没有了**。

### 失败提示「没有可用的原始外链」

说明这条已经本地化，而且这台机器上没存过它的来源。解决办法：在详情面板的 `audioUrl` 字段里手工填回原始外链，保存后再重抓。原始出处一般能在 `audioSource` 字段的署名里找到。

## 九、右侧详情 · 字段区

13 个字段，逐个说明。

| 字段 | 界面标签 | 填写规则 | 校验级别 |
|------|---------|---------|---------|
| `name` | 中文名 | 2–8 字，全表唯一，不含空格标点 | 重名 = 错误；字数越界 = 提醒 |
| `scientific` | 学名 | 拉丁双名法：`Passer montanus`（属名首字母大写 + 空格 + 小写种加词） | 格式错 / 重复 = 错误 |
| `group` | 类群 | 下拉三选一：鸟类 / 蛙类 / 昆虫 | 其它值 = 错误 |
| `protectLevel` | 保护级别 | 下拉选基础级别 + 可选补充说明 | 格式错 = 错误 |
| `callFeature` | 叫声特征 | 建议 20–120 字 | 越界 = 提醒 |
| `habit` | 习性 | 建议 20–120 字 | 越界 = 提醒 |
| `distribution` | 分布 | 建议 10–80 字 | 越界 = 提醒 |
| `funFact` | 趣味知识 | 建议 20–140 字 | 越界 = 提醒 |
| `audioUrl` | 音频地址 | `https://` 外链，或 `/audio/<id>.<ext>` 本地路径 | 用 http:// = 错误；扩展名不在 `.mp3/.m4a/.wav/.ogg` = 错误 |
| `audioSource` | 音频来源 | 见下方「版权署名」 | 要素缺失 = 提醒 |
| `audioLicense` | 授权协议 | 下拉四选一 | 其它值 = 错误 |
| `image` | 插画 | 由 id 自动派生，**不要手改** | 与 id 不匹配 = 错误 |
| `id` | （不在字段区） | 主键，改动要走专门流程 | 见第十一章 |

### 保护级别怎么填

拆成了两个输入框防手抖：

- **左边下拉**（必选）：国家一级重点保护野生动物 / 国家二级重点保护野生动物 / 国家三有保护动物 / 未列入国家保护名录
- **右边输入框**（可选）：补充说明，1–20 字。填了会自动拼成 `国家二级重点保护野生动物（某某种群）` 这种格式，中文全角括号由工具自动加

### 插画字段

`image` 恒等于 `/assets/npc-<id>.webp`，由 id 派生。手改会报错。旁边有「按 id 生成」按钮可以一键修正。

如果对应的插画文件不存在，会有提醒（不拦保存）——前端有 SVG 剪影兜底，不会开天窗。

### 版权署名区（粉色底，合规红线）

这两个字段被单独放在粉色区块里，**契约要求默认可见、不得折叠**，就是为了让人没法忽略它。

**`audioSource` 四要素**，缺一个提醒一次：

```
Xeno-canto XC777570 录制者：张三 2023-05-12 浙江杭州西溪湿地
└── 平台      └─ 编号   └── 录制者      └── 日期    └── 地点
```

工具会检查：长度是否够 20 字、有没有编号（`#1595435` 或 `XC777570` 格式）、有没有「录制者」三个字、有没有 `YYYY-MM-DD` 日期。

**`audioLicense` 四选一**：`CC0` / `CC BY` / `CC BY-NC` / `CC BY-NC-SA 4.0`

填 `CC BY-SA`、`ARR`、`未知` 这类枚举外的值 = 错误，拦保存。

### 契约外字段

如果某条数据带了 13 个字段之外的键，字段区底部会提示「该条含契约外字段：xxx（工具会原样保留，不会丢）」。

这是**保护机制**：工具不认识的字段照样存回去，绝不静默删除。

## 十、保存流程

改动是**草稿态**的——改了不会立刻写盘，都攒着，直到你点保存。

### 完整链路

```
你改字段
   ↓
草稿变化（顶栏保存按钮变成「保存（N 条改动）」）
   ↓
0.5 秒后自动体检（后台校验，实时更新顶栏错误数）
   ↓
点「保存」→ 弹出 diff 预览窗口
   ↓
逐条确认改动（红色 - 是旧值，绿色 + 是新值）
   ↓
点「确认写入」
   ↓
服务端再校验一次 ── 有错误 → 拒写，原文件纹丝不动
   ↓ 通过
自动备份 species.sample.json.bak.20250811-143022
   ↓
按固定字段顺序整理，整体写回 JSON
```

### 四道保险

1. **实时体检**：每次改动 0.5 秒后自动校验，顶栏错误数实时更新，不用等到保存才发现问题
2. **diff 预览**：写盘前必须看一遍改了什么，防误操作
3. **服务端二次校验**：前端校验可能被绕过，服务端会独立再验一次，有错误级问题**直接拒绝写入**
4. **自动备份**：每次写入前把原文件复制成 `species.sample.json.bak.<时间戳>`，改坏了可以直接复制回来

> 备份文件已被 gitignore，不会污染仓库。它是本机快照，攒多了可以手动删。

### 误关页面保护

有未保存改动时，关标签页或刷新会弹系统确认框。这是刻意的，防止辛苦写的文案一把丢掉。

### 常见困惑

| 困惑 | 答案 |
|------|------|
| 点「保存」按钮是灰的 | 没有任何改动，或者正在处理中 |
| diff 里「确认写入」是灰的 | 有错误级问题，先去修红色项 |
| 上传了音频但 JSON 没变 | 上传只落盘，`audioUrl` 还在草稿，**要点保存** |
| 点了「重新载入」，改动全没了 | 这个按钮就是丢弃改动重读磁盘。点之前会有确认框 |

## 十一、修改 id（联动改名）

**`id` 是主键，改它是所有操作里最危险的一个**，所以走独立流程。

### 为什么危险

一个 id 同时被**四个地方**引用：

1. `src/data/species.sample.json` 的 `id` 字段
2. 插画文件名 `public/assets/npc-<id>.webp`
3. 本地音频文件名 `public/audio/<id>.mp3`
4. `src/data/recognition-map.json` 里指向它的映射值

**只改一处，就会产生悬空映射（识别命中后白屏）和图片 404。**

### 怎么改

1. 点字段区右上角「修改 id（联动改名）」
2. **前提：不能有未保存改动**（改名会直接写盘，会冲掉草稿）。有改动的话工具会拦住你，先保存或重新载入
3. 输入新的 kebab-case id（小写字母数字，连字符分隔，如 `eurasian-tree-sparrow`）
4. 点「预览改动」——工具会列出**将要执行的每一步操作**
5. 看清楚再点「确认执行」

### 会自动做的

- 改 `species.sample.json` 里的 `id` 和 `image`
- 物理重命名插画文件
- 物理重命名本地音频文件，并同步 `audioUrl`
- 改 `recognition-map.json` 里所有指向它的键（保持原键顺序，只换值）
- 搬移 `.audio-origins.json` 里的来源存档
- **两个 JSON 都会先备份**（`species.sample.json.bak.<ts>` 和 `recognition-map.json.bak.<ts>`）

### 不会自动做、需要人工跟进的

那是前端代码，工具**不碰代码文件**，需要手工同步。改完告诉郝栈桥一声，或者自己改（就是把数组里的旧 id 换成新 id）。

## 十二、数据完整性规则（重要，请务必遵守）

这些规则不是建议，是**契约**（`src/data/ADMIN_SCHEMA.md`）。工具的校验器和写入逻辑都是按它实现的。

### 1. 不丢字段

写回时，契约里的 13 个键**无论有没有值都保留**（空值写成空字符串，不是删掉键）。契约之外的未知字段**原样追加在末尾**。

**任何情况下都不会静默丢字段。** 这条是工具实现的硬约束，你不用担心手滑弄丢东西。

### 2. 逐条署名不可破坏

`audioSource` / `audioLicense` 是**逐条独立的版权信息**，代表这一条音频的真实出处。

- 禁止批量覆盖（工具已硬性拦截）
- 禁止为了「看起来整齐」把不同来源的音频填成同一个署名
- 换了音频，署名必须同步换

**这是合规红线，不是格式洁癖。** 素材署名不实，作品可能被判违规。

### 3. 整体读写回

工具**永远是整个数组一起读、整个数组一起写**，不做局部补丁。

好处：不会出现只写了一半导致 JSON 结构损坏的情况。
代价：**同一时间只能有一个人在编辑。** 两个人同时开着 AdminTool 改同一个文件，后保存的会覆盖先保存的。

> **约定：改数据前在群里说一声，避免撞车。**

### 4. 固定字段顺序

写回时严格按这个顺序序列化：

```
id → name → scientific → group → callFeature → habit →
distribution → protectLevel → funFact → audioUrl →
audioSource → audioLicense → image
```

**为什么**：顺序固定，git diff 才干净——只显示你真正改动的那几行，而不是整个文件重排。这让代码审查和回滚都变得可行。

格式细节：UTF-8 无 BOM、LF 换行、2 空格缩进、中文不转义成 `\uXXXX`、文件末尾有换行。这些工具全自动处理，你不用管。

### 5. id 是主键

- 必须 kebab-case：`^[a-z0-9]+(-[a-z0-9]+)*$`
- 全表唯一
- 改动必须走第十一章的联动改名流程

## 十三、关于 recognition-map.json

### 它是什么

学名 → 物种 id 的映射表，**属于识别域**，是识别链路的关键一环：

```
BirdNET 返回学名 "Passer montanus"
   ↓ 查 recognition-map.json
得到 speciesId "eurasian-tree-sparrow"
   ↓ 查 species.sample.json
渲染这张科普卡
```

结构是扁平的键值对：

```json
{
  "Passer montanus": "eurasian-tree-sparrow",
  "Eurasian Tree Sparrow": "eurasian-tree-sparrow"
}
```

一个物种可以有多个键（学名 + 英文名 + 同物异名 + 拼写变体），都指向同一个 id。

### AdminTool 对它做什么

工具**只读**这个文件，用来做两项校验：

| 检查 | 级别 | 说明 |
|------|------|------|
| 某物种的学名没出现在映射表的键里 | **提醒** | 该物种识别命中后查不到卡片，等于「识别得出来但展示不了」 |
| 映射表里某个键指向的 id 在物种库里不存在 | **错误** | 悬空映射，识别命中后会白屏。**拦保存** |

工具**不提供**编辑映射表的界面（只在联动改名时会自动改它的值）。要增删映射键，直接用编辑器改 `src/data/recognition-map.json`。

### 改它的注意事项

1. **改动等于改识别行为**，不是改文案。加错一个键，可能让某个声音被识别成完全不相干的物种。
2. **必须和前端消费契约一致。** 前端 `src/lib/recognize.ts` 同时兼容两种结构：
   - 扁平：`{ "学名": "speciesId" }`  ← **当前用的是这种，保持不变**
   - 嵌套：`{ version: 1, map: { "学名": { speciesId, aliases: [] } } }`

   **不要随意在两种结构之间切换。** 真要改，先和郝栈桥确认。
3. **值必须是物种库里真实存在的 id。** 填错会被工具判为悬空映射（错误级），保存 `species.sample.json` 时会被一起拦下。
4. **空字符串是有意义的**：`"某学名": ""` 表示「明确不收录这个物种」，前端会给出「识别到 X（暂未收录）」而不是当作没识别到。这是刻意设计，别当成脏数据清掉。
5. 改完回 AdminTool 点「重新载入」，顶栏的映射表键数和校验结果会刷新。

## 十四、日常工作流示例

### 场景 A：给某个物种换一段更好的音频

1. `npm run dev` → 打开 `/#/dev`
2. 搜索框输物种名，点开
3. 先听一遍现有音频，确认确实要换
4. 右侧「上传修正音频」选新文件（**勾着规范化**）
5. 等提示写入成功，回左边试听新音频确认效果
6. **更新 `audioSource` 和 `audioLicense`**——换了音频署名必须跟着换
7. 顶栏点「保存」→ 看 diff → 确认写入

### 场景 B：批量清理音频质量

1. 左侧勾选要处理的条目（或「全选」）
2. 点「规范化音频」
3. 看批量执行结果面板，失败的单独处理
4. 顶栏「保存」写回 `audioUrl`

### 场景 C：例行数据体检

1. 打开工具，看顶栏红色错误数
2. 勾上「只看有错」，列表只剩问题条目
3. 逐条点开修（错误信息就显示在对应字段下方，红色 ✕ 是错误，橙色 ! 是提醒）
4. 修到顶栏变绿色「✓ 校验通过」
5. 保存

### 场景 D：新增一个物种

工具目前**不支持在界面上新增条目**。新增要手工在 `species.sample.json` 里加一条（13 个字段齐全），然后：

1. 回工具点「重新载入」
2. 用校验器查漏补缺
3. 上传音频、补插画、在 `recognition-map.json` 里加映射键

## 十五、故障速查

| 现象 | 原因 | 处理 |
|------|------|------|
| 「管理员工具连不上后端」 | 不是用 `npm run dev` 启动的 | 用 `npm run dev`，不要用 `preview` 或直接开 dist |
| 保存报「有 N 处校验未通过」 | 有错误级问题 | 勾「只看有错」逐条修。**原文件没被改动，不用担心** |
| 上传报「转码失败」 | 源文件损坏或格式异常 | 换个文件试；用播放器确认源文件能正常播放 |
| 「规范化音频」按钮是灰的 | 没装 ffmpeg | 装 ffmpeg 后重启 `npm run dev` |
| 重抓报「没有可用的原始外链」 | 已本地化且本机没存过来源 | 在 `audioUrl` 手工填回外链，保存后再重抓 |
| 改 id 被拦住 | 有未保存改动 | 先保存，或点「重新载入」放弃改动 |
| 校验提示「悬空映射」 | `recognition-map.json` 指向了不存在的 id | 去映射表里改掉或删掉那个键 |
| 提示「学名未出现在映射表键里」 | 该物种够不到识别链路 | 在 `recognition-map.json` 补键（提醒级，不急） |
| 提示「插画未补齐」 | `npc-<id>.webp` 不存在 | 提醒级，前端有剪影兜底，不影响演示 |
| 改坏了想回滚 | — | 找 `src/data/` 下最新的 `species.sample.json.bak.<时间戳>`，复制回来覆盖即可 |

## 十六、一句话记住这些

1. **`npm run dev` → `http://localhost:5173/#/dev`**，地址里的 `#` 不能少

6. **改 id 走联动改名**，别手改
